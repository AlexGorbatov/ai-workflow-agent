# ai-workflow-agent v1.0.0

An AI agent that answers freight quote requests from email: it reads the request, looks the customer up in the
CRM over MCP, prices the lane from carrier rates, applies YAML rules, and either replies on its own or asks an
approver — then records the opportunity and follows up. Durable on PostgreSQL, audited end to end, and the
model never sets a price.

## Try it

```bash
git clone https://github.com/AlexGorbatov/ai-workflow-agent.git && cd ai-workflow-agent
./scripts/demo.sh        # Docker + JDK 25, no API key
```

Then open the operator UI at http://localhost:8080/ui/ (`max` / `max`), Mailpit at http://localhost:8025 and
Grafana at http://localhost:3000.

## Highlights

- **Durable workflow without a workflow cluster.** Own state machine on PostgreSQL and db-scheduler: step journal,
  retries with backoff, timers for clarifications, approvals and follow-ups, signals from email and the UI.
  ([ADR 0001](../adr/0001-own-engine-on-db-scheduler.md), [ADR 0002](../adr/0002-immutable-context-in-jsonb.md))
- **Prompt injection cannot move money.** The model extracts and writes; pricing and policy are code and YAML;
  every number in a reply is checked against the quote, with a template fallback.
  ([ADR 0003](../adr/0003-llm-without-tools-code-computes-money.md))
- **Safe external writes.** Mail through an outbox with stable Message-IDs; the CRM write needs an HMAC approval
  token for exactly that amount plus an idempotency key, and the CRM verifies the token itself.
  ([ADR 0004](../adr/0004-outbox-and-approval-token.md))
- **Human in the loop.** Approval inbox with the policy's reasons, a price breakdown and a short briefing;
  approve with another price, reject, or retry from a step; SLA escalation. Keycloak roles.
- **Observable.** Traces per step, tool and model call; business metrics and model cost in a Grafana dashboard.
- **Evaluated.** 40 labelled cases in five languages with thresholds for intent, fields, route and injection
  recall, run weekly against a real model.

## Known limitations

- Eval labels are drafts and no real-model eval run is published yet; the build checks the harness with a stub.
- One workflow type; no workflow versioning (see ADR 0001).
- The approval-token secret is symmetric and shared with the CRM (see ADR 0004).
- The demo GIF is still to be recorded.
